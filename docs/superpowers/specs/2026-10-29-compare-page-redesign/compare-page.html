Privacy

Where your file goes.

Every other tool hands the file to a server or a kernel, even when that runs on your own machine. Here, the page you are reading is the only place it goes.

Grey stops are someone else’s computer. Outlined stops can run code.

Markdown

Markdown files, too.

Open a .md file from your disk and it reads like a notebook. Edit it in the page you are reading, then save it back to the same file.

  • Opens .md and .markdown by picking or dropping
  • Edit the rendered text: double-click a paragraph, or press e
  • A bar for bold, italic, code, links, headings and lists, with undo
  • Save writes the same file in Chromium browsers; others download a copy

Which to choose

Each one is right for something.

Pick by the job, not the logo.

ipynb viewerReads

To read a notebook now, on any device, with nothing to install and nothing sent anywhere, including one that came by email.

nbviewerShows

For a stable public address that anyone can open without this tool or an account.

GitHub previewShows

When the notebook lives in a repository and you are reviewing it there, beside the code.

Google ColabRuns

To run it with no setup, on Google’s machines, when a Google account and Drive are fine.

JupyterLabRuns

To work on it: run cells, change code, install packages, on a kernel you control.

VS CodeRuns

When it is part of a codebase you are editing and debugging, with git beside it.

What it does not do

Said plainly, so the ticks above can be trusted.

  • Run code. You see what the notebook saved, never new results.
  • Live widgets. They need a kernel; their saved picture shows if there is one.
  • Edit code or outputs. Only the text of text cells changes.
  • Export to PDF. The browser’s print dialog does that.
  • Markdown from a link. Markdown files open from disk.
